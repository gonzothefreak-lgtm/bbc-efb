# SimConnect function dictionary

MSFS 2020 SDK **0.24.6.0**, Windows x64. Inventory checked **24 November 2026**.

All **91** SimConnect function declarations in the installed [SDK header](<C:/MSFS SDK/SimConnect SDK/include/SimConnect.h>) matched by name against **91** exports in the installed x64 DLL. The DLL export table was read from disk. This check made no DLL loads, SimConnect calls or simulator connections. Microsoft’s [MSFS 2020 API reference](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/SimConnect_API_Reference.htm) provides behaviour and parameter details. The SDK header is the source for exact prototypes. [Inventory verification](../reference/01_CODEX_WORK_EVIDENCE/test_artifacts/core_sdk_dll_expanded_preflight_2026-11-24/REPORT.md) checks the current seven-status table: Core path 13, Offline path 47, Experimental 3, Host helper 4, Deprecated 22, Unsupported 1, Header only 1. The [first inventory check](../reference/01_CODEX_WORK_EVIDENCE/test_artifacts/core_simconnect_dictionary_2026-11-24/REPORT.md) recorded the earlier four-status table (13 Core path, 54 Pending, 22 Deprecated, 2 Header only) and fails against this page by design. The offline test `tests/test_repo_dictionary.py` repeats the repository-side part of the check: every implemented row matches the adapter's SDK declarations.

| Status | Meaning |
|---|---|
| **Core path** | Used by the current direct adapter. Its symbol resolved in a load-only preflight. Current behaviour is supported by offline evidence. |
| **Offline path** | Implemented in the direct adapter and exercised with an in-memory SDK. The export resolved during the expanded load-only check. Simulator runtime behavior remains unverified. |
| **Host helper** | Implemented and tested offline as an adapter diagnostic or buffer/transport helper. It is outside the consumer API. |
| **Experimental** | Retained in the public API at the owner's request. The SDK documents possible silent behavior in MSFS 2020. Treat dispatch without a reply as unverified. |
| **Pending** | Present in the header and DLL. Core has no implementation for the function yet. |
| **Deprecated** | Microsoft marks the function as deprecated or replaced. Export presence alone provides no basis for use. |
| **Unsupported** | Microsoft documents a runtime support limitation despite the header declaration and DLL export. |
| **Header only** | Present in the header and DLL. This review found no matching Microsoft MSFS 2020 reference entry for the function. |

The current adapter uses **67** functions, including experimental operations and host helpers. All 67 resolved in the expanded guarded load-only check. Live callback-based probes on the Asobo 747-8i and PMDG 737-800BCF exercised the selected read-only connection, telemetry and aircraft Input Event discovery paths. Most rows still await live validation. The list describes the underlying provider surface. Modules use capability IDs from the [Core Consumer API guide](05_CORE_AND_SIMCONNECT.md#consumer-api-developer-guide). Use Microsoft’s [SimVar index](https://docs.flightsimulator.com/html/Programming_Tools/SimVars/Simulation_Variables.htm) for variable names and units and the [Event ID index](https://docs.flightsimulator.com/html/Programming_Tools/Event_IDs/Event_IDs.htm) for simulator command names. Both are inputs to the Core data dictionary. MSFS 2024 has its own [SDK reference](https://docs.flightsimulator.com/msfs2024/retail/programming-apis/simconnect/simconnect-sdk/) and requires separate inventory and validation. ## Reference discrepancies

- The SDK declares and exports `SimConnect_RequestFacilitiesList`. The dedicated page uses the spelling `RequestFacilitesList`. The table uses the exact exported name. [Microsoft facility list page](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/API_Reference/Facilities/SimConnect_RequestFacilitesList.htm)
- `SimConnect_ExecuteAction` has a dedicated page even though the index omits it. `SimConnect_ExecuteMissionAction` is a separate deprecated function. [ExecuteAction reference](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/API_Reference/General/SimConnect_ExecuteAction.htm) · [MSFS 2020 API index](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/SimConnect_API_Reference.htm)
- `SimConnect_CameraSetRelative6DOF` is declared and exported with no matching MSFS 2020 API reference entry found. Microsoft lists `SimConnect_SetSystemState` as unsupported. [System state packet reference](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/API_Reference/Structures_And_Enumerations/SIMCONNECT_RECV_SYSTEM_STATE.htm)
- `DispatchProc` is a callback type defined by the client. It is documented separately from the 91 callable exports. Core supports callback dispatch through `SimConnect_CallDispatch` with this callback type and pull dispatch through `SimConnect_GetNextDispatch`. Only callback dispatch has passed a live read-only probe. [Callback reference](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/API_Reference/General/DispatchProc.htm)

For deployment, account for every row with an implementation and verification status or a documented SDK limitation. Record the module-facing API operation where applicable and any simulator or aircraft prerequisites. Core-owned connection and dispatch functions support the shared session used by modules. Aircraft Input Events and Client Data are distinct groups with separate request, response and access requirements.

The general SimVar and client event API reuses the current data definition, object data request and write, and event mapping and transmission functions. A module can call the documented scalar and fixed-width text SimVars and simulator events through Core without a starter catalog entry. [Consumer API and example](05_CORE_AND_SIMCONNECT.md#general-simvars-and-client-events)

Round 3 adapter behaviour (offline evidence only, no row status changes): a `changed_only` grouped snapshot leaves the clock datums out of its `SimConnect_AddToDataDefinition` definition, because SimConnect's TAGGED flag still sends a clock-only packet whenever any datum changes; refused snapshot fields are remembered for the life of the demand; COM1 is read as FLOAT64 Hz, rounded to whole Hz with a 100 Hz readback tolerance, and `COM SPACING MODE:1` is read before a standby frequency is sent; a rejected facility-cache unsubscribe (`SimConnect_UnsubscribeToFacilities_EX1`) starts a 2-60 s backoff instead of tainting the session; early removals that the initial facility snapshot re-lists are dropped; VOR and NDB replies report no region because the schema has no identity fields; Input Events prime from the first change value after every `SimConnect_GetInputEvent` attempt fails; a catalog request during an `SimConnect_EnumerateInputEvents` enumeration restarts it; discrete events go to the never-evicted control lane; and `SimConnectProvider.wake()` signals the SDK wake event. [Consumer API guide](05_CORE_AND_SIMCONNECT.md#audit-fixes-round-3)
