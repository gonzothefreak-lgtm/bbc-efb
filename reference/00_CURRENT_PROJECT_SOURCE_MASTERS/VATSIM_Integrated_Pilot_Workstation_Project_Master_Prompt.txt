2. PROJECT VISION

Our goal is to create a fully integrated VATSIM pilot workstation and Electronic Flight Bag (EFB).

The application should consolidate the tools, information and workflows that VATSIM pilots currently access through multiple separate programs and browser windows.

The main problem we want to solve is:

Having to constantly switch between different applications while flying on VATSIM.

We want to create a unified desktop environment that brings together flight planning, dispatch, navigation information, network awareness, pilot communications, weather, simulator connectivity and flight logging.

The application should feel like a purpose-built aviation workstation, rather than a collection of unrelated tools.

Our priorities are:
1. Reliability and stability.
2. Efficient aviation workflows.
3. Ease of use during flight.
4. Professional interface design.
5. Integration with existing flight simulation software.
6. Modular architecture.
7. Customisation and flexibility.
8. Local-first operation.
9. Long-term maintainability.
10. Expandability.

The application does not yet have an official name. We will decide on its identity and branding later.

- Microsoft Flight Simulator.

Rather than simply displaying several unrelated programs inside one window, we want the different systems to work together wherever technically possible.

For example, retrieving a SimBrief flight plan could automatically populate relevant information throughout the application.

We should explore interface concepts such as:
- A unified cockpit workspace.
- Modular panels.
- Resizable sections.
- Dockable interface components.
- Customisable layouts.
- Multiple workspaces.
- Flight-phase-specific views.
- Persistent flight information.
- Quick-access controls.
- Multi-monitor support.

The interface should prioritise the information pilots need during an actual VATSIM flight. It should be practical, responsive and visually professional.

10. LOCAL DATA STORAGE

I prefer a local-first application.

The software should not require a cloud account or mandatory external database to operate.

Configuration, pilot profiles, aircraft profiles, flight records and application data should be stored locally wherever practical.

Preferred storage formats include:
- JSON.
- JSONL.
- TXT.
- CSV for exports.

Do not introduce SQLite or other database technologies without first discussing their benefits, limitations and necessity.

External services such as VATSIM, SimBrief and Active Sky may require network access or independently installed software.

The application should handle unavailable external services gracefully.
